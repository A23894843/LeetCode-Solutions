## `01 // SYSTEM OVERVIEW`

This repository documents my ongoing journey in **Data Structures and
Algorithms (DSA)**. Each solution is a reference point for understanding
an algorithm, improving implementation quality, and preparing for coding
interviews.

**Primary goals** - Strengthen logical thinking and algorithmic
problem-solving. - Recognize reusable patterns instead of memorizing
solutions. - Compare approaches by time and space complexity. - Keep
solutions organized for revision and interview preparation. - Improve
code clarity, correctness, and efficiency over time.

> **Learning principle:** Solve the problem first, understand why the
> solution works, then look for a better one.

## `05 // HOW TO USE`

### Clone the repository

``` bash
git clone https://github.com/A23894843/LeetCode-Solutions.git
cd LeetCode-Solutions
```

### Browse a problem

Open a problem folder and review the source file. Many LeetCode
submissions use the platform's expected `class Solution` interface and
are designed to be pasted into LeetCode, not run as standalone programs.

For a source file that includes its own `main()` function and required
headers, compile with a C++17 compiler:

``` bash
g++ -std=c++17 solution.cpp -O2 -Wall -Wextra -o solution
./solution
```

Replace `solution.cpp` with the actual filename. If a file relies on
LeetCode-provided declarations or omits a `main()` function, submit it
through the LeetCode editor or create a separate test harness.

## `06 // PROBLEM-SOLVING PIPELINE`

``` text
[ Read the statement ]
          |
          v
[ Check constraints and edge cases ]
          |
          v
[ Identify a pattern ]
          |
          v
[ Implement a correct baseline ]
          |
          v
[ Analyze time and space ]
          |
          v
[ Optimize, test, and revise ]
```

For each problem, the target workflow is to: 1. Understand the
requirements and constraints. 2. Work through examples and edge cases.
3. Choose an appropriate data structure or algorithm. 4. Verify
correctness before optimizing. 5. State time and auxiliary-space
complexity. 6. Revisit the solution when a clearer or more efficient
approach is found.
